## 1. 结论先行（v2 主线）

**把 AutoSolver 从"跑一次求解器"升级成"动态调度实验台"，并让"自主学习"在动态曲线上自己显形：**

> 时间轴不断产生订单、骑手不断移动；每个时间片由感知层判定当前 regime（早高峰/午高峰/低意愿/骑手稀缺…），据此选择策略组合，对未锁定订单做滚动求解、冻结已派出决策。屏幕左边是固定贪心基线，右边是 AutoSolver；底部曲线把"打分"翻译成业务指标（平均配送 ETA / 每单成本 / 准时率 / 覆盖率）实时对比。右屏当前采纳路径用**发光流动粒子线**呈现。**底部曲线额外画第三条"暖启动 AutoSolver"线——它带累积的场景识别记忆，随这一天推进，它的场景识别命中率往上爬、业务指标相对"冷启动"拉开差距，这条"冷暖差"就是"自主学习的过程和结果"。**

对外答辩让评委依次看到三件事（正好对上导师的三个交付重点）：

1. **最终结果好不好**：同一订单流、同一时钟、同一指标，右屏明显比左屏贪心稳。
2. **为什么不是固定算法（机制 > 算法）**：系统按 regime 动态选策略组合并维护 best-so-far；"不缺算法，缺的是这套可迁移的机制"。
3. **自主学习怎么体现**：进化的是**场景识别**（识别更准→选策略更对→结果更好），通过 memory 召回在相似场景复用；现场不改正式 solver、不联网改代码。

## 4. 动态求解：定义 + A 方案（MVP）+ B+ 方案（推荐升级）

### 4.1 先把"动态求解"讲对（答辩口径）

不要把动态求解说成"线条动起来"——那只是展示层。本项目的动态求解定义为：

> 在仿真时钟推进过程中，订单、骑手位置、接单意愿、路况风险不断变化。系统每隔一个时间片重新构造**当前可决策窗口**，对未锁定订单做**滚动求解**；已派出且不可撤销的决策**冻结**，未完成或新进入窗口的订单继续参与下一轮优化。

它比"静态算例跑一次再播放动画"强，因为它体现了：①订单陆续到达、不是一次性全知；②高峰压力变化影响策略选择；③系统随时要有可行解、又利用剩余时间继续改进；④同一动态输入下，AutoSolver 比固定贪心更稳。这就是调度领域的 **receding horizon / rolling horizon control**，正好回应导师"纵向扩展：静态仿真 → 动态跨时间片求解"。

### 4.2 A 方案（第一版必须落地，风险最低）

```text
输入：large_seed301（或 generated_cases 里的样例候选行）
预处理：给订单合成 arrival_minute / deadline_minute / merchant、courier 坐标（仿真层，打"演示"角标）
时钟：每 tick = 若干仿真分钟，推进一整天 0–1440
每个 tick：
  1. 注入当前时间片新到订单
  2. 更新骑手状态：available / assigned / moving / finished
  3. 左屏跑 greedy baseline（_fallback_official_greedy）
  4. 右屏跑 AutoSolver portfolio（solver.solve / run_case_agent）
  5. 冻结本 tick 已派出订单
  6. 记录 成本 / ETA / 准时率 / 覆盖率 / 耗时 / 当前策略
输出：DynamicSolveStep 序列，前端本地播放
```

优点：实现快、稳。缺点：算法层"动态性"还能更强、还没把"自主学习"画出来——这正是 B+ 补的。

### 4.3 B+ 方案（推荐升级，答辩亮点）＝ 感知驱动滚动时域 + 记忆冷暖三泳道

这是 v2 的核心升级。两个支柱：

**支柱一：感知驱动滚动时域（讲"机制 > 算法" + "纵向扩展"）**

```text
触发重算：新订单进入 / 骑手完成上一单 / 流量突增 / 某指标跌破阈值
滚动窗口：只优化未来 20–30 分钟内可决策订单；已接单/已出发路线冻结
策略路由（regime → 策略组合，机制的核心）：
  平峰        → greedy + single_multidispatch        （求快）
  午高峰      → disjoint_gain + pair_matching + production_solver（求组合收益）
  低意愿/雨天 → low_global_column + sparse_cover      （控接单风险）
  骑手稀缺    → scarce_k2_column + scarce_bundle_mcf  （保覆盖、控复用）
```

这把"动态求解"从"重复跑算法"提升成"调度系统常用的滚动时域控制"，且贴合本项目已有的 anytime portfolio / regime / best-so-far 机制。

**支柱二：记忆冷暖三泳道对照（把"自主学习的过程和结果"画出来，且诚实）**

底部曲线区放**三条线**（不是三张地图——地图只画两张，避免导师批评的"信息密度低/看不清"）：

| 泳道 | 含义 | 学不学习 |
|---|---|---|
| Greedy 基线 | 固定贪心，永远不学 | 否 |
| AutoSolver 冷启动 | 有机制（感知→选策略→滚动求解），但 memory 清空，每个 tick 都"第一次见这个场景" | 机制有、记忆无 |
| AutoSolver 暖启动 | 同一机制 + 累积的 场景→策略 记忆，相似场景直接召回最优策略组合 | 机制有、记忆有 |

随这一天推进：
- 暖启动的**场景识别命中率/置信度**曲线往上爬（命中即"这个 regime 我以前见过、知道该上哪套策略"）。
- 暖启动的业务指标（ETA/成本/准时率）相对冷启动**逐步拉开差距**。
- 这条"冷暖差"＝**"自主学习的过程（曲线在爬）+ 学习的结果（最终更优）"**，正好是导师红标 30:33 要的东西。

**为什么这版更强、又不撒谎**（关键，照着讲不翻车）：
- "学习"发生在**场景识别 + 记忆召回**层，这是真机制（`evolution.py` 的 registry / similarity 召回、`strategy_registry.json` 的 `target_regime`/`accepted` 真实存在），不需要现场联网、不改正式 solver。
- 完全对齐导师纠正："进化的是对场景的识别，不是求解器。"
- 冷暖对照是**同源对比**：同一订单流、同一时钟、同一指标，唯一变量是"有没有记忆"，可审计、抗"是不是拿不同算例比"的质疑。

> 落地降级路径：先做 A 方案两泳道（Greedy / AutoSolver）跑通双屏；再把第三条"暖启动"泳道叠上去。即使第三条来不及，前两条也已满足会议主诉求。

底部三条线：橙色是贪心，蓝色是没有记忆的 AutoSolver，青绿色是带记忆的 AutoSolver。
随着这一天推进，青绿线越来越好——因为系统对场景的识别越来越准。
注意：我们进化的不是求解器本身，而是它对场景的识别能力；
正式 solver 不被现场修改，自主学习发生在隔离的实验轨道里，失败会自动回退。

### 6.2 直接移植的代码（新建 `flow_route_v2.js`）

把以下函数从源 app.js 抽出、合并成一个对外接口 `renderFlowRoute`。下面是已整理好的可落地版本（基于源 :765-941 真实实现改写）：

```javascript
// flow_route_v2.js —— 源自 提交版原版/web_agent_demo/static_rg/app.js:765-941
const SVGNS = "http://www.w3.org/2000/svg";
const REDUCE_MOTION = window.matchMedia("(prefers-reduced-motion: reduce)").matches;

function svgEl(tag, attrs) {
  const n = document.createElementNS(SVGNS, tag);
  for (const k in attrs) n.setAttribute(k, attrs[k]);
  return n;
}
function addAnim(node, tag, attrs) {           // 减弱动效时不挂 SMIL，元素静态可见
  if (!REDUCE_MOTION) node.appendChild(svgEl(tag, attrs));
  return node;
}
// Catmull-Rom → 贝塞尔：让路线像绕路的城市路网，而非直线
function smoothPath(points) {
  const p = points;
  if (!p || p.length < 2) return "";
  if (p.length === 2) {
    const a = p[0], b = p[1];
    const mx = (a[0]+b[0])/2, my = (a[1]+b[1])/2, dx = b[0]-a[0], dy = b[1]-a[1], k = 0.14;
    return `M ${a[0]},${a[1]} Q ${(mx-dy*k).toFixed(1)},${(my+dx*k).toFixed(1)} ${b[0]},${b[1]}`;
  }
  let d = `M ${p[0][0]},${p[0][1]}`;
  for (let i = 0; i < p.length-1; i++) {
    const p0=p[i-1]||p[i], p1=p[i], p2=p[i+1], p3=p[i+2]||p2;
    const c1x=p1[0]+(p2[0]-p0[0])/6, c1y=p1[1]+(p2[1]-p0[1])/6;
    const c2x=p2[0]-(p3[0]-p1[0])/6, c2y=p2[1]-(p3[1]-p1[1])/6;
    d += ` C ${c1x.toFixed(1)},${c1y.toFixed(1)} ${c2x.toFixed(1)},${c2y.toFixed(1)} ${p2[0]},${p2[1]}`;
  }
  return d;
}
// 彗星：亮头 + 渐隐拖尾，沿同一路径错开 begin（粒子感）
function cometAlong(layer, points, dur, group, phase = 0) {
  const D = parseFloat(dur) || 2.6;
  const pathD = smoothPath(points);
  const trail = [[3.4,1,0],[2.4,0.55,0.05],[1.6,0.32,0.1]];   // [半径, 透明度, begin偏移]
  trail.forEach(([rr, op, off], i) => {
    const dot = svgEl("circle", { r: rr, fill: "#eafffb", opacity: op });
    dot.dataset.group = group;
    if (i === 0) dot.setAttribute("filter", "url(#pinGlow)");
    if (REDUCE_MOTION) {
      if (i === 0) { const pp = points[Math.floor(points.length/2)]||points[0];
        dot.setAttribute("cx", pp[0]); dot.setAttribute("cy", pp[1]); layer.appendChild(dot); }
      return;
    }
    dot.appendChild(svgEl("animateMotion", { dur,
      begin: ((phase+off)*D).toFixed(3)+"s", repeatCount: "indefinite", path: pathD }));
    layer.appendChild(dot);
  });
}
// 对外唯一接口：把一条采纳路线渲染成红框那种四层流动粒子线
function renderFlowRoute(layer, points, opts = {}) {
  const cyan = opts.color || "#1cf4d2";
  const dur  = opts.durationMs ? (opts.durationMs/1000)+"s" : "2.7s";
  const group = opts.id || "route";
  const d = smoothPath(points);
  // ① 发光底
  layer.appendChild(svgEl("path", { "data-group": group, d, fill: "none",
    stroke: "rgba(28,244,210,.2)", "stroke-width": 7.5, "stroke-linejoin": "round",
    "stroke-linecap": "round", filter: "url(#glow)", "vector-effect": "non-scaling-stroke" }));
  // ② 青主线 + 箭头
  layer.appendChild(svgEl("path", { "data-group": group, d, fill: "none", stroke: cyan,
    "stroke-width": 3.4, "stroke-linejoin": "round", "stroke-linecap": "round",
    "marker-end": "url(#arrow)", filter: "url(#glow)", "vector-effect": "non-scaling-stroke" }));
  // ③ 流动能量虚线（流动感）
  const flow = svgEl("path", { "data-group": group, d, fill: "none",
    stroke: "rgba(224,255,250,.9)", "stroke-width": 1.8, "stroke-dasharray": "0.1 10",
    "stroke-linecap": "round", "vector-effect": "non-scaling-stroke" });
  addAnim(flow, "animate", { attributeName: "stroke-dashoffset", values: "0;-10.1",
    dur: "0.8s", repeatCount: "indefinite", calcMode: "linear" });
  layer.appendChild(flow);
  // ④ 彗星粒子（粒子感）
  if (opts.active !== false) cometAlong(layer, points, dur, group, opts.phase || 0);
}
```

## 7. 自主策略与三层 memory 设计（导师说"比算法内核还重要"）

### 7.1 对外讲"四角色"，内部落到现有真实模块

老师问"几个 agent"，对外说四个**角色**（不虚构多个独立进程）：

| 对外角色 | 内部模块 | 真实出处 |
|---|---|---|
| 感知 Agent | Perception | `system.py:22`、`infer_regime`、`features`、`perception` 事件(:409) |
| 策略 Agent | Planner + Controller | `_initial_strategies` / `_adaptive_strategies` / 预算控制，`round_start` 事件 |
| 执行评估 Agent | Executor + Critic | strategy runner / `system.py:32 critic` / `attempt_result` 事件 |
| 记忆进化 Agent | Memory + Evolution | `evolution.py: EvolutionManager` / `evolution_memory.jsonl` / `strategy_registry.json` |

### 7.2 三层 memory

| 层 | 名称 | 存什么 | 落地 |
|---|---|---|---|
| L0 | 运行态 | 当前 tick、best-so-far、已冻结订单、正在评估的策略 | `DynamicSolveStep.agent_events` + 前端运行状态 |
| L1 | episode | 每次策略生成/校验/试跑/接受拒绝/耗时/原因 | `autosolver_agent/evolution_state/evolution_memory.jsonl` |
| L2 | strategy | 哪类场景下哪些策略有效、失败原因、召回相似度 | `strategy_registry.json` 的 `target_regime`/`accepted`/`last_reason` + similarity 排序 |

一句话讲法：**"L0 是这一次调度正在发生什么；L1 是这个场景历史上试过什么；L2 是什么策略在什么场景下值得复用。"**

### 7.3 自进化闭环（诚实版）

```text
Generate → Safety Gate → Sandbox → Critic → Memory → Recall
```

- `evolution_generate` 生成实验策略 → `evolution_validate` 安全门 → `evolution_trial` 沙箱试跑（显示耗时/reason）→ 接受进候选记忆 / 失败 `evolution_rollback` 回退（不污染正式 solver）→ `evolution_recall` 相似场景召回。
- **不要讲成"现场 LLM 一定越跑越高"。** 现场热路径零 LLM；真 LLM 离线进化只走录屏线（见 §11）。

2. `657.104` 是**本地口径**（贪心 2097.658→657.104，−68.7%，确定性），**不冒充官方 654.2935**。
3. 成本与 ETA/准时率走**两条独立计算路径**：成本走 `solver.py:1647 _solution_expected_cost`；**ETA 来自路径几何，不调成本函数**（防"第二目标自拆"）。
4. `deadline` / 坐标 / ETA 是**仿真合成层**，一律打"演示"角标。
5. "自主学习"＝**场景识别 + 记忆召回**（真机制），不等于"现场进化求解器"。对齐导师："进化的是对场景的识别。"
6. `large_seed301` 是**唯一未硬编码的干净算例**，现场动态仿真主跑它。
7. Agent 是"四个**角色**由统一控制器编排"，**不虚构多进程**。
